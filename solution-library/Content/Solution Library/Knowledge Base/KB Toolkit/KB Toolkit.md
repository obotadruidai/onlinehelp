title: KB Toolkit
---


The KB Toolkit solution template equips you with essential tools to effectively manage KB Metadata and generate missing questions for unstructured data sources. It also provides comprehensive test tools enhancing your knowledge management processes. You can import test cases from Excel, create test plans and iterations, and compare results effortlessly. Additionally, you have the capability to download test results for further analysis using Excel.

## Solution Benefits

* **Proof of Concept**: Demonstrate AI Agent accuracy to clients during the acceptance phase.
* **Experimentation**: Test various LLMs and prompts to find optimal combinations.
* **AI Agent Governance**: Conduct automated tests with test data, analyze results, and refine content without disrupting user experience.

## Considerations

No intents are added to your AI Agent. All Flows (automations) are triggered from the workspace and do not include train phrases. Therefore, they do not affect the end user conversation experience.

## Prerequisites

* Tenant Druid community (open new tenant [here](https://www.druidai.com/license-activation)) or Druid subscription.
* You should have a AI Agent. For information on how to create an AI Agent, see [Creating AI Agents](https://druidai.gitbook.io/druid-ai-docs/ai-platform/build-ai-agents/authoring-tools/creating-ai-agents).
* Ensure you have a Druid Portal service account with full permissions.
* You should have the Knowledge Base feature active on your tenant. If you want to activate it for your tenant, get in touch with [DRUID Support Team](mailto:support@druidai.com?subject=Activate%20KB%20for%20my%20tenant).
* You should have data sources added to the KB and the KB trained.
* You should have Druid.LLM service enabled on your tenant or an Azure OpenAI subscription. To activate Druid.LLM service, reach out to [DRUID Support](../../../Solution%20Library/Knowledge%20Base/KB%20Toolkit/mailto:support@druidai.com).

## How to use the solution

1. Import and set up the solution.
2. Create test cases.
3. Create test plans to group test cases for focus.
4. Run tests.
5. Analyze iterations.
