<a id="TestDruidSIPCalls"></a>


{% hint style="info" %}
**Info:** This feature is available starting with Druid 9.27.
{% endhint %}

The Test Call feature provides a sandbox environment to verify your speech services and evaluate how your AI Agent responds in real time before connecting your system to a live call center environment.

{% hint style="info" %}
**Info:** To simplify testing, the test call completely disregards the configured Sip FQDN, IP whitelisting, and connection type settings.
{% endhint %}

<a id="Prerequisite"></a>

## Prerequisite

You only need to configure and enable your Speech-to-Text (STT) and Text-to-Speech (TTS) services under the **Speech** tab before launching a test. For more information, see [Step 3. Configure the speech services](Configure%20Druid%20SIP%20Connectivity.md#Step).

<a id="RunaTestCall"></a>

## Run a Test Call

Follow these steps to initiate a test call with your AI Agent:

1. Go to your AI Agent configuration page.
2. Navigate to **Channels** > **Druid SIP**.
3. On the **General** tab, click the **Test Call** button.

![](../Resources/Images/druid%209.27/test%20call%20button.png)

The Test Call modal window appears. You can choose to open it in a new window.

4. Click **Start test** call.

![](../Resources/Images/druid%209.27/start%20test%20call_998x758.png)

5. Grant the browser permission to access your microphone if prompted.
6. Speak into your microphone to interact with the AI Agent.
7. You can adjust your input and output volume using the **Mic volume** and AI Agent **volume** sliders during the call.
{% hint style="info" %}
**Info:** The Test Call modal contains an **Include debug messages** toggle that lets you alternate between two diagnostic views during the call and after it ends. For more information, see the subsequent section.
{% endhint %}

8. Click **Hang up** to end the call session and **Close** to close the modal.

<a id="MonitorandTroubleshootCallLogs"></a>

## Monitor and Troubleshoot Call Logs

The Test Call modal features an **Include debug messages** toggle that lets you alternate between two diagnostic views:

- **Technical Debugging (Toggle ON)** -When enabled, the console displays detailed, real-time connectivity and signaling events during the call and after it ends. This view is ideal for engineering teams to verify:

- Microphone access status.
- ICE server connectivity and WebRTC connection states.
- Signaling WebSocket communication and SDP negotiation.

![](../Resources/Images/druid%209.27/test%20call%20window.png)

- **Conversation Transcript (Toggle OFF)** - When disabled, the console displays a clean, real-time conversation transcript. Use this view to review conversational flow accuracy:

- **STT** (Speech-to-Text). Shows exactly how the speech engine transcribed your voice inputs.
- **TTS** (Text-to-Speech). Shows the text generated by the AI Agent that is synthesized back into audio.

![](../Resources/Images/druid%209.27/test%20call%20without%20debug%20msg.png)

<a id="ReviewTestCallHistory"></a>

## Review Test Call History

Every completed test call is recorded in the Conversation History for later audit and dialogue diagnostics. To prevent confusion with live production traffic, all test calls are automatically assigned the **(testcall)** label in the records.

![](../Resources/Images/druid%209.27/test%20call%20in%20CH.png)
